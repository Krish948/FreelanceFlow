# FreelanceFlow

**Keep client work, projects, time, and invoicing connected.**

FreelanceFlow is a role-based workspace for freelancers and their clients. It brings everyday work management into one Supabase-backed app, with separate experiences for each role.

## Features

- **Client and project management** — organize accounts, work, deadlines, and budgets.
- **Task tracking** — manage project tasks and status from freelancer and client workspaces.
- **Time tracking** — use a persistent timer or add time manually.
- **Invoices and finances** — create invoices, review payment status, and view financial summaries.
- **Project orders** — freelancers can review open orders; accepted orders become active projects.
- **Collaboration** — support for shared project updates, deliverables, messages, and notifications.
- **Plans** — Free and Pro access rules are enforced by the application and database.

## Security and data

Freelancer and client workspaces are separated by database-backed roles and protected routes. Supabase row-level security scopes business data to its owner; client views expose only information shared with that client.

Sensitive operations are kept on the server or in database functions. In particular, keep the Supabase service-role key server-side, use the authorized invoice-creation flow, and do not bypass the database policies from the browser.

The timer keeps its running state in browser storage, while saved time is calculated from timestamps.

## Getting started

### Requirements

- Node.js 20+ and npm, or Bun
- A Supabase project

### Install and run

```bash
git clone https://github.com/Krish948/FreelanceFow.git
cd FreelanceFow
npm install
```

Create a local `.env` file in the project root and add the [required environment variables](#environment-variables). Then start the development server:

```bash
npm run dev
```

Open the local URL printed by Vite.

You can use Bun instead of npm:

```bash
bun install
bun run dev
```

## Environment variables

Set these values in your local `.env` file:

| Variable | Purpose |
|---|---|
| `SUPABASE_URL` | Supabase project URL |
| `SUPABASE_PUBLISHABLE_KEY` | Publishable key used by the app |
| `SUPABASE_SERVICE_ROLE_KEY` | Server-side operations that require elevated access; configure only when needed |

Optional `VITE_` variables can be used to configure the browser client explicitly:

```dotenv
VITE_SUPABASE_URL=https://<project-ref>.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=<publishable-key>
VITE_SUPABASE_PROJECT_ID=<project-ref>
```

**Never put `SUPABASE_SERVICE_ROLE_KEY` in a `VITE_` variable or commit it to Git.** The `.env*` pattern is ignored by `.gitignore`; use your deployment platform's secret manager for production values.

### Google sign-in

Enable Google under **Authentication → Providers** in the Supabase Dashboard and configure its OAuth credentials. Add the Supabase-provided callback URL to the Google OAuth client, and allow your app's local and deployed `/auth` callback URLs in Supabase's URL Configuration.

## Database migrations

Database changes are stored in `drizzle/migrations`. Apply migrations to your Supabase project using your established migration workflow, and only apply migrations that have not already run.

For project orders, migrations `0005_project_orders_marketplace.sql`, `0006_activate_accepted_project_orders.sql`, and `0007_repair_accepted_project_orders.sql` are applied in order. If the first two are already applied, apply `0007` to repair the acceptance flow and existing accepted orders.

## Project structure

```text
drizzle/
  migrations/       SQL schema changes
src/
  components/       Shared and feature-specific UI
  integrations/     Supabase and Lovable integrations
  lib/              Data, role, timer, and application helpers
  routes/           File-based TanStack routes
  test/             Automated tests
supabase/           Supabase project configuration
```

`src/routeTree.gen.ts` is generated by TanStack Router; edit route files under `src/routes/` instead.
